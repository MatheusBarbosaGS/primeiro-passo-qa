Projeto guiado: seu primeiro portfólio

Um único projeto bem feito, do manual à automação, conta mais do que dez tutoriais pela metade.

  1. Escolha um sistema e escreva o plano de testeUse o Sauce Demo. Defina o que será testado (login, carrinho, checkout), o que fica de fora e quais riscos você enxerga.
  2. Escreva 15 a 20 casos de teste em GherkinInclua caminhos felizes e negativos: senha errada, carrinho vazio, campos obrigatórios em branco.
  3. Execute e reporte os bugs que encontrarO site tem usuários com problemas propositais. Escreva os bug reports seguindo o modelo "Aprovado" logo abaixo.
  4. Automatize os cenários principaisCom Selenium e Java, usando Page Objects e Cucumber para ligar os cenários Gherkin ao código.
  5. Adicione testes de APICrie uma coleção no Postman para o ServeRest e, depois, automatize os mesmos testes com RestAssured.
  6. Rode tudo numa pipeline e capriche no READMEConfigure o GitHub Actions para rodar os testes a cada push e explique no README como executar o projeto. Uso o GitHub Actions aqui porque é gratuito e fica junto do seu portfólio. Nas empresas é comum encontrar Jenkins ou GitLab, que aparecem na trilha, e a lógica é a mesma.

Modelo de bug report

Escrever um bom bug report é a habilidade nº 1 de um QA: o dev precisa reproduzir o problema sem te chamar no chat. Compare:

ReprovadoBUG-?
Título: Login não funciona

O login tá dando erro, arruma aí pfv.
AprovadoBUG-142
Título: Login exibe erro 500 com e-mail em maiúsculas
Ambiente: Homologação · Chrome 130 · Windows 11
Severidade: Alta
Passos:
  1. Acessar /login
  2. Informar "MARIA@TESTE.COM" e senha válida
  3. Clicar em "Entrar"
Resultado esperado: Usuária acessa o painel
Resultado obtido: Tela "Erro 500"
Evidência: print + log do console anexados
Obs.: Com e-mail em minúsculas funciona
